# primitive_db

Учебный проект: консольное приложение, имитирующее работу с базой данных.
Информация о таблицах хранится в файле `db_meta.json`.

## Установка и запуск

Запуск в режиме разработки:

```
uv sync
uv run database
```

Установка как самостоятельной программы:

```
uv build
uv tool install dist/primitive_db-0.4.0-py3-none-any.whl
database
```

## Управление таблицами

| Команда | Описание |
|---|---|
| `create_table <имя_таблицы> <столбец1:тип> <столбец2:тип> ...` | создать таблицу |
| `list_tables` | показать список всех таблиц |
| `drop_table <имя_таблицы>` | удалить таблицу |
| `help` | справочная информация |
| `exit` | выход из программы |

Поддерживаемые типы данных: `int`, `str`, `bool`.

Столбец `ID:int` добавляется в начало каждой таблицы автоматически.

### Пример использования

```
>>>Введите команду: create_table users name:str age:int is_active:bool
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool

>>>Введите команду: create_table users name:str
Ошибка: Таблица "users" уже существует.

>>>Введите команду: list_tables
- users

>>>Введите команду: drop_table users
Таблица "users" успешно удалена.

>>>Введите команду: drop_table products
Ошибка: Таблица "products" не существует.

>>>Введите команду: abc
Функции abc нет. Попробуйте снова.

>>>Введите команду: create_table users age:float
Некорректное значение: age:float. Попробуйте снова.
```

## CRUD-операции

Данные каждой таблицы хранятся в отдельном файле `data/<имя_таблицы>.json`.

| Команда | Описание |
|---|---|
| `insert into <имя_таблицы> values (<значение1>, <значение2>, ...)` | создать запись |
| `select from <имя_таблицы>` | прочитать все записи |
| `select from <имя_таблицы> where <столбец> = <значение>` | прочитать записи по условию |
| `update <имя_таблицы> set <столбец> = <новое_значение> where <столбец_условия> = <значение_условия>` | обновить запись |
| `delete from <имя_таблицы> where <столбец> = <значение>` | удалить запись |
| `info <имя_таблицы>` | информация о таблице |

Правила ввода значений:

- строки записываются в кавычках: `"Sergei"`;
- числа без кавычек: `28`;
- логические значения: `true` или `false`;
- значение `ID` не указывается: оно генерируется автоматически;
- все поля обязательные, количество значений должно совпадать с числом столбцов без `ID`.

### Пример использования

```
>>>Введите команду: insert into users values ("Sergei", 28, true)
Запись с ID=1 успешно добавлена в таблицу "users".

>>>Введите команду: select from users where age = 28
+----+--------+-----+-----------+
| ID |  name  | age | is_active |
+----+--------+-----+-----------+
| 1  | Sergei |  28 |    True   |
+----+--------+-----+-----------+

>>>Введите команду: update users set age = 29 where name = "Sergei"
Запись с ID=1 в таблице "users" успешно обновлена.

>>>Введите команду: delete from users where ID = 1
Запись с ID=1 успешно удалена из таблицы "users".

>>>Введите команду: info users
Таблица: users
Столбцы: ID:int, name:str, age:int, is_active:bool
Количество записей: 0

## Обработка ошибок и подтверждение действий

### Обработка ошибок

Все операции с базой данных обёрнуты в декоратор `handle_db_errors`. Программа не падает при ошибках, а выводит понятное сообщение и ждёт следующую команду:

```
>>>Введите команду: select from products
Ошибка: Таблица "products" не существует.

>>>Введите команду: insert into users values ("Anna", "25", true)
Некорректное значение: 25. Попробуйте снова.
```

### Подтверждение опасных действий

Перед удалением таблицы (`drop_table`) и удалением записей (`delete`) программа спрашивает подтверждение. Любой ответ, кроме `y`, отменяет операцию:

```
>>>Введите команду: drop_table users
Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]: n
Операция отменена.

>>>Введите команду: delete from users where ID = 1
Вы уверены, что хотите выполнить "удаление записи"? [y/n]: y
Запись с ID=1 успешно удалена из таблицы "users".
```

### Замер времени и кэширование

- Для операций `insert` и `select` выводится время выполнения: `Функция select выполнилась за 0.001 секунд.`
- Результаты одинаковых запросов `select` кэшируются. Кэш сам перестаёт использоваться, когда данные таблицы меняются.
